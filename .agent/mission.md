## What exists today (v1.6.0, released)
Windows tray app in C# (.NET 10, WinForms + WebView2) that converts Uzbek typed in the
old Latin spelling to the reformed alphabet at word boundaries: sh→ş, ch→ç, o'→ö, g'→ğ,
case preserved, apostrophe exceptions (Is'hoq, mus'haf), 9 apostrophe variants,
hyphenated ordinals (5-chi→5-çi), chat slang (yaxwi boldi→yaxşi böldi). It self-updates
from GitHub Releases (asset YangiAlifbo.exe, tag vX.Y.Z, SHA-256 digest required).

- src/Core/UzbekPhonetics.cs: letter rules
- src/Core/LanguageDetector.cs: "is this word Uzbek?": English/code reject list →
  lexicon → suffix stripping (402 suffixes, consonant alternation, voice suffixes,
  ordinals)
- src/Core/ChatNormalizer.cs, src/Core/TextConverter.cs, src/Core/Updater.cs
- src/Win32/: keyboard/mouse hooks, focus + password-field detection, SendInput
- src/UI/: tray, WebView2 control center (src/UI/Web/: HTML/CSS/JS + bundled fonts)
- src/Core/Dictionaries/uzbek_words.txt: 948,288 lines, ~14 MB, GENERATED by
  build_dictionaries.py from ~32,000 roots (uzwords_raw.txt), both spellings
- src/Core/Dictionaries/english_reject.txt: 10,057 entries
- docs/: GitHub Pages site; docs/assets/js/engine.js is a JS port of the letter rules
- tests/ (257 MSTest tests), e2e_tests/ (270)
Measured: lexicon load ~430 ms, RAM ~157 MB, lookup ~1 µs.
Design tokens (use everywhere): lapis #13205C, deep #0E1846, porcelain #EEF1EC,
ink #0F1530, turquoise #2FB3A6, saffron #F0B23A (saffron only for the new diacritics
and the primary action). Fonts: Unbounded (display), Commissioner (text), both OFL,
already in src/UI/Web/fonts/.

## Hard rules
1. Work on branch `multiplatform` (sub-branches allowed, merged into `multiplatform`).
   Push it. NEVER push to main, NEVER create tags or GitHub releases, NEVER publish
   to any store, NEVER sign with real certificates. Every installed copy

3. The shared test vectors (Workstream A) are the source of truth. Every engine
   implementation on every platform must pass them before you call it done.
4. Converting an English word is worse than missing an Uzbek word. Never accept a
   change that raises English false positives on the eval set.
5. Do not touch the untracked scripts in the repo root (add_vocab.py,
   bump_version.py, patch_*.py, update_suffixes.py). Do not change the shipped
   Windows app's behaviour except in Workstream H.

   log it, or store it. Only the Windows updater talks to the network.
7. Password fields must never be converted on any platform (use each OS's
   secure-field signals; verify, don't assume).

## Workstreams
Start A and B first; they unblock the rest. C–H then run in parallel; I last.

### A. Ground truth
- tools/vectors: console project referencing src/YangiAlifbo.csproj that writes
  test vectors from the CURRENT engine: all lexicon entries (old spelling), all
  reject words, and several thousand generated cases (casing, 9 apostrophe
  variants, hyphens, ordinals, chat slang, punctuation). Fields: input,
  ShouldConvert(Strict), ShouldConvert(Aggressive), ChatNormalizer.Normalize,
  UzbekPhonetics.Convert, TextConverter.Convert for sentence cases. Commit the
  generator; commit vectors compressed (or a deterministic sample + generator).
- tools/eval: real-text set of Uzbek sentences from a public source (record source
  and licence) plus English/code text, with expected output. Never train on it.
  Script reporting English false positives and Uzbek misses for any engine.
- tools/bench: baseline size, load time, RAM, latency of the current engine.

### B. Compact data + Rust core
1. Coverage experiment: can ~32K roots + the suffix analyzer recognise all 948K
   generated forms? Report % and failure categories; build the minimal exceptions
   list for 100%. Store one spelling only.
2. Compact read-only binary data file (FST via the `fst` crate is fine): roots,
   exceptions, reject list; memory-mappable; documented in data/FORMAT.md.
3. `yangi-core` in Rust: port UzbekPhonetics, LanguageDetector (ordinals, voice
   suffixes, alternation), ChatNormalizer, TextConverter. Pure; only I/O is reading
   the data file. Must pass 100% of the vectors.
4. FFI (C ABI + headers), wasm build, benchmarks vs. baseline.
Acceptance: 100% vector parity; size, RAM, load, latency reported vs. baseline.

### C. Unknown-word model
Char n-gram classifier (hashed 1–5 grams, logistic regression; tiny char-CNN only
if clearly better), int8-quantized, documented export format, inference in
yangi-core (no ML runtime). Used only for words not in the dictionary; reject list
and user lists always win. Tune the threshold on a validation split (not eval) so
English false positives do not rise. Report size, latency, eval results vs. the
current engine. Behind a setting, default OFF.

### D. Browser extension
Manifest V3 for Chrome/Edge (Firefox if cheap) using the wasm core: converts at
word boundaries in inputs, textareas, contenteditable; skips password/email/url
inputs; per-site enable/disable; popup with on/off and Strict/Aggressive; keeps
caret position. Playwright tests on real pages. Package zip in CI.

### E. Android keyboard
Kotlin InputMethodService. Evaluate forking FlorisBoard (Apache-2.0) vs. a minimal
keyboard; record the decision. Uzbek Latin layout with keys or long-press for
ş ç ö ğ; converts the word before the cursor on space/punctuation via yangi-core
(JNI); one backspace right after a conversion undoes it; respects password and
no-suggestion input types. Settings screen (Strict/Aggressive, chat slang). Unit +
instrumented emulator tests in CI. Unsigned debug APK artifact.

### F. macOS
